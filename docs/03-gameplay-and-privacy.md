# 03 对局流程与隐私

更新：2026-10-06。状态：网页版体验流程草案，不固定实现状态枚举。

## 一局的完整过程

1. 创建房间：选择板子与公开规则，指定公共播报设备。
2. 入场准备：玩家加入，确定座位、昵称，完成试音和准备确认。
3. 私密发牌：每人确认本人身份，随后默认遮蔽；未完成准备不进入首夜。
4. 夜晚：按板子依次呼叫角色，开放各自秘密行动窗口，收束并闭眼。
5. 黎明：统一结算本夜动作，按公告政策公布死亡。
6. 死亡反应：有合法反应者可执行或放弃；完成反应链后判胜。
7. 白天：若未结束，线下讨论与投票，房主确认录入结果。
8. 白天死亡反应与判胜：完成所有应处理反应，再进入下一夜或结束。
9. 局后：解释胜负、按确认的政策展示身份与记录；保留席位开始新局。

暂停、音频恢复和连接恢复可发生在过程中。它们不能隐式改变玩家身份、药剂或已经确认的行动。

## 公共主持节奏

每个角色窗口由“开眼播报、行动时间、收束、闭眼播报”组成。尚未播完开眼指令时不能因为有人提前操作而开始下一段；公共结束时间也不能随秘密行动完成速度明显变化。

- 未配置角色可以从公开流程中省略，因为配置本来就是公开信息。
- 已配置角色死亡或资源耗尽后，仍保留约定的公开呼叫和掩护窗口，避免暴露其状态。
- 玩家提前完成不必一直盯屏，提交后可以遮蔽屏幕等待。
- 只告诉公共视角“等待当前窗口结束”或“连接恢复中”，不告诉谁没行动、哪个角色离线。
- 死亡结果在约定的公告时点公开，不因服务器先完成计算而提前改变公共存活名单。

具体时长、延长次数和超时选择由 [规则决策 D05](02-rules-and-decisions.md) 确定。

## 三种视角的信息边界

| 信息 | 玩家本人 | 房主控制视角 | 公共播报视角 |
| --- | --- | --- | --- |
| 房间规则、座位、已公告存活状态 | 可见 | 可见 | 可见 |
| 本人的身份与既有私密记录 | 私密可见 | 不因房主权限获得 | 不可见 |
| 他人身份及未公告夜晚行动 | 不可见；狼人仅按规则看队友提议 | 不可见 | 不可见 |
| 预言家查验、女巫刀口与药剂 | 仅对应合法角色可见 | 不可见 | 不可见 |
| 谁尚未执行秘密行动 | 不公开；角色内部协作按规则处理 | 不可见 | 不可见 |
| 连接状态与暂停 | 本人可见，公开提示不关联角色 | 可处理全员连接异常 | 只显示不泄密的公共提示 |
| 局后身份与复盘 | 按已确认的局后政策 | 相同政策 | 相同政策 |

一个人可以同时是房主和玩家，但必须切换视角。公共投屏或播报界面不能借用包含本人身份的玩家页面。

## 暂停、恢复与更正

- 刷新或短时断线恢复原座位、本人视角和已确认行动，不重复发牌或重复消耗资源。
- 请求中与已经确认是不同状态；玩家应知道行动是否真正被系统接受。
- 单台玩家设备异常时给出重试和恢复路径；超过约定等待期再进入不泄密的公共暂停流程。
- 播报网页离开前台、播放失败或失联时，冻结尚未开始的公共窗口，恢复后继续当前有效内容，不补播全部旧台词。
- 房主出局仍保留组织权限。房主真正离线时按事先确定的接管流程转交，不向接管者开放全员身份。
- 白天结果先确认再公布；只在尚未产生新私密信息的边界内允许更正，并保留可理解的更正记录。

## 保密底线

隐藏界面文字不等于信息保密，交给设备的数据本身就应符合权限。私人声音、震动、角色专属待机颜色和阶段长短也需要检查。出局玩家不能看到后续秘密行动；猎人仅在合法待处理反应中获得一次性行动入口。
