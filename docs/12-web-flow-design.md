# 12 手机网页流程与交互设计

更新：2026-10-08。状态：网页交互基线；正式声音与云端验收见 [22](22-production-voice-game-acceptance.md)，本次取消身份确认见 [23](23-identity-viewing-without-confirmation.md)。最终视觉基线见 [MASTER](../design-system/werewolf-web/MASTER.md)。

页面围绕线下聚会的当前任务组织。所有人都是玩家，房主只是额外承担公开主持和维护；不增加观战席、第二播报设备或接管入口。玩法以 [02](02-rules-and-decisions.md) 为准。

## 页面结构

| 路由 | 首屏任务 | 次级入口 |
| --- | --- | --- |
| `/` | 选择创建或加入；同一浏览器有最近房间时提供继续 | 公开规则 |
| `/new` | 昵称、8 至 12 人、候选板子、胜负模式、确认建房 | 受限自定义与角色规则 |
| `/join?room=房间号` | 核对房间配置、输入昵称、加入 | 已开始、满员、失效的错误状态 |
| `/r/房间号` | 按公开阶段呈现大厅、统一待机、私密任务、白天或结束 | 座位、规则、本人记录；房主另有主持入口 |
| `/r/房间号/recap/对局编号` | 本局参与者查看全部身份与逐夜记录 | 同一浏览器有资格查看的其他局 |

女巫、预言家、狼人等身份不进入 URL、页面标题、浏览器通知或埋点。用体验状态切换房间内容，不建立暴露身份的角色路由。私密页不是公共播报页的额外设备。

## 创建与入场

1. 浏览器先完成一次会话初始化，等待 Cookie 成功设置后再发送建房或加入请求。初始化只能有一个进行中的任务，避免两个新凭据互相覆盖。
2. 创建页默认屠边，人数与配比清晰列出；切换人数同时更新候选板子。人数胜负规则用分段选择，角色数量用数字步进输入，不把候选配置宣传为经过平衡验证的推荐。
3. 邀请链接和二维码只包含房间号。加入前读取邀请摘要，带上当前大厅编号提交；迟到请求不能加入重开的新大厅。
4. 大厅固定显示座位号与昵称，准备状态可公开。选择空座位或修改昵称会撤销本人的准备；房主改变配置会撤销所有准备。
5. 同一 Cookie 已在房间时直接恢复原座位，不按昵称创建第二身份。会话失效不提供取回身份码，也不允许房主读取别人的身份帮助恢复。
6. 房主在同一页面选择文字或未来的语音主持。当前可实现的模式只有文字；正式语音选项须阶段 4 的真实试音通过后开放。
7. 满员且全员准备后房主开始发牌。成员不足、准备不足或主持手机不可用时，开始操作不可用并显示对应状态。

已加入但有另一标签页停在大厅时，收到新的对局编号应丢弃本地旧草案并切到当前局，不能自动重发准备或开局请求。

## 身份与统一待机

发牌后所有手机首先显示同一牌背与通用“查看身份”操作。私密面板只显示本人角色和能力摘要，不提供“确认身份”按钮或“身份已确认”状态，也不记录查看进度。收起后恢复相同待机外观。发牌播报完成且主持可用后，房主可直接开始第一夜，不等待全员查看或确认；也不提供逐人查看列表。大厅全员准备与夜间行动确认保留。

私密面板采用可点击的查看与收起，不把按住、滑动或长按设为唯一操作。切到后台、切换路由、刷新和恢复前台时立即遮蔽；草案和私密数据不写入 LocalStorage，不在公共播音中朗读。保持牌背、背景、亮度、目标区大小和过渡效果统一，不能用角色专属颜色或通知声提示本人该行动。

所有角色在夜晚都看到统一的公共阶段与“查看当前任务”入口。页面处于前台且服务器确认本人可行动时，自动打开本人私密面板；包括狼人协商与公告结束后的猎人反应。死亡神职、资源耗尽的女巫及其他非行动玩家不弹出。每个逻辑行动轮次只自动打开一次，主动关闭或切后台隐藏后不因轮询、暂停恢复重复弹出；未曾打开的新行动可在返回前台后打开。入口仍允许手动查看。不使用角色专属常驻按钮、通知声或系统通知。

## 夜晚行动

公开流程固定为守卫、狼人、女巫、预言家，未配置角色省略；已配置但死亡或耗尽的角色仍完整播报并保留本角色同长窗口。开眼指令完成后才开始守卫30秒、狼人15秒、女巫和预言家10秒计时；猎人公告完成后有10秒操作时间。狼人超时后自动等待共同确认，无手动暂停入口。

| 本人角色 | 私密任务 | 确认后的状态 |
| --- | --- | --- |
| 守卫 | 存活目标；本人可选；上一夜连续目标禁用；“不守”是明确选项 | 已接受的目标或不守，不能更改 |
| 狼人 | 存活目标或共同空刀；显示队友提议与确认状态 | 全体同目标且共同确认才锁定；此前可修改提议 |
| 女巫 | 仍有解药时显示狼刀目标；选择解药、毒药或不用药 | 一次确认锁定一种选择，不提供第二瓶药操作 |
| 预言家 | 其他存活目标或放弃；允许重复查验 | 私密显示阵营结果，不显示具体职业 |
| 猎人和平民 | 同一等待面板，无常规夜晚行动 | 等待公开窗口，不提示其他人是否完成 |

目标按固定座位排列，姓名与座位号同时出现。没有选中目标时不能把空值自动解释为放弃；“不守”“空刀”“不查验”“不用药”和猎人“放弃开枪”都必须主动选中后确认。

2026-10-08 单屏行动补充：目标、角色状态、倒计时和确认同时出现在首屏，短竖屏使用四列，横屏使用左右布局。规则、完整长昵称和查验历史通过私密详情入口查看；目标长昵称单行省略，但座位号与可访问全名保留。仅调整展示，不改变行动时长或提交规则。最新尺寸矩阵与完整流程验收见 [21](21-single-screen-action-acceptance.md)，此前按钮常驻方案见 [20](20-pre-play-flow-fixes.md)。

女巫目标是狼刀目标，不是最终死亡名单。首夜可自救，之后自救禁用；守救叠加仍可正常存活，毒药不被守护或解药抵消。毒药可选本人。解药用尽后的新夜不再显示新的狼刀目标；本夜已看到的信息收起再展开仍可查看。

狼队更改任一提议后，所有旧共同确认消失；提交共同确认携带私密提议版本。如果版本过期，重新加载当前目标并要求本人再次确认，不能自动替用户确认新目标。最终锁定后仅保留已接受状态，公开倒计时继续正常走完。

当前任务标题

[ 1 号 / 昵称 ]   [ 2 号 / 昵称 ]
[ 3 号 / 昵称 ]   [ 4 号 / 昵称 ]

## 房主的同机主持

房主的玩家主屏与其他人相同。主持图标打开独立的维护抽屉，只有公开指令、当前有效播报、文字或声音状态、暂停和恢复，不展示他人私密任务或未提交名单。

| 公开阶段 | 房主控制 | 推进条件 |
| --- | --- | --- |
| 私密发牌 | 开始首夜 | 发牌播报完成且主持可用，不要求逐人查看或确认 |
| 开眼指令 | 确认当前指令完成 | 当前公开指令编号匹配，文字确认或未来音频实际结束 |
| 行动窗口 | 暂停，不提供提前结束 | 服务端固定截止时间到达 |
| 闭眼指令 | 确认当前指令完成 | 进入下一角色或内部夜间结算 |
| 黎明 | 发布出局公告 | 公共名单只在此时改变，必要时进入猎人反应 |
| 白天 | 录入、确认待发布、发布 | 只处理当前草案，发布前可改，发布后不可撤销 |
| 暂停 | 恢复、中止；未来可切文字主持 | 原房主前台心跳恢复，并明确继续 |
| 结束 | 复盘、下一局 | 新大厅保留席位但所有人重新准备 |

文字模式下“当前指令完成”是房主确认已经传达，而不是假装播放完音频。语音模式下排队器只能消费当前指令编号，不能用旧 `ended` 事件打开新窗口。

语音播完后推进请求若失败，主页面和主持控制提供原回执重试；网络结果未知则沿用原请求重试。不得因重试重复播放已完成的台词，也不得把旧回执迁移到新窗口。

房主死亡后仍能组织；私人面板按出局规则收缩，主持入口保留。失联时没有转交主持的操作。维护抽屉关闭不停止公共播音，打开私密面板也不应中断公共播音。

同浏览器使用 BroadcastChannel 与短期租约协调活跃主持页，其他页不争抢心跳。明确选择当前页面不改变房主身份，也不是换设备接管。未来播放器须沿用此协调并补充多标签页声音检查。

## 黎明与猎人

内部计算结束到正式公告之间，所有公开座位仍保留此前的存活状态，不显示死亡人数、死因或猎人操作。发布后一次更新名单；普通身份保持未知，猎人公开身份。

被毒的猎人没有开枪入口，也不能由房主代开；包括同时被狼刀和毒药作用的情况。有资格的猎人本人显示其他存活目标与明确的放弃选择。其他人只看到公开的待处理反应，不获得其目标草案。放弃后仍保留已公开身份，结算完反应才判胜。

## 白天录入

白天页面显示已公布的座位状态和事件，讨论、警长、平票与遗言留在线下。房主打开录入面板，流程如下：

1. 明确选择一个存活玩家或“本轮无人出局”，生成私有草案。
2. 展示座位与昵称的核对摘要，确认后变为待发布。
3. 独立的“发布结果”操作结算并改变公共状态；涉及出局时用简短确认对话框防误触。
4. 发布前修改目标产生新的草案编号并撤销旧确认。另一标签页或迟到请求携带旧编号时被拒绝。
5. 暂停不清空未发布草案。恢复后重新同步当前窗口编号，保留已经确认的草案；不自动发布。

本地改选尚未保存时，禁止确认或发布旧草案；保存后重新核对。最终发布确认绑定草案编号，另一标签页修改草案不能沿用此前的确认。

发布后不提供撤销按钮。严重误录只能明确“中止本局”，复盘显示中止，不伪造赢家；下一局重置秘密状态。

## 反馈与恢复

| 状态 | 页面行为 |
| --- | --- |
| 本地草案 | 允许修改，不显示已提交 |
| 请求中 | 防止重复点击，保留当前目标；不阻挡私密遮蔽 |
| 已接受 | 服务器已保存才显示回执，恢复时从本人视图读取已接受动作 |
| 网络结果未知 | 使用原请求编号和原内容重试；不能换编号再次消耗药剂 |
| 局或窗口过期 | 先遮蔽和重新同步，清除旧草案；不自动迁移行动到新窗口 |
| 提议或草案过期 | 加载最新私密版本，重新要求本人确认 |
| 公开暂停 | 通用“对局已暂停”，不公布哪个角色未操作；房主处理恢复 |
| 会话失效 | 显示原身份无法恢复，不按名字认领座位；大厅可重新加入，开局后不可替换 |
| 房间到期 | 结束访问，不恢复旧秘密数据；返回创建或加入 |

前台每秒公共同步，后台降为每 5 秒；房主前台每 3 秒心跳，失联 10 秒暂停。服务端在同步、心跳或动作请求中检查截止时间。客户端倒计时只用于显示，不提交客户端时间，也不自行判胜。

私密视图在面板打开、本人请求恢复，或前台新行动窗口需要判断自动打开资格时读取。资格检查以服务器的本人行动字段为准，不根据公共阶段推断身份；窗口过期或请求期间离开前台不展示返回数据。离开前台收起面板并停止私密轮询。全体玩家的公开轮询节奏一致，公开版本号不随秘密动作增加。恢复先读当前对局，不补播全部历史语音。

## 结束与复盘

胜负页允许本局参与者进入复盘，查看全部身份、各夜目标和结算；中止局明确标记中止。可查看的对局列表由参与资格过滤，不是房间全部历史。

“下一局”回到保留席位的大厅，清理私密面板、旧草案、请求中状态与全部语音队列。配置可重新选择；新加入者不能看到旧局复盘。普通玩家可退出大厅，房主不能在游戏中通过退出隐式转交权限。

## 视觉与组件规范

采用已确定的炭黑、暗红与冷绿方向，不使用搜索建议中不适合本产品的赌场绿金、营销首屏或复杂 3D。正式角色、牌背和场景位图在阶段 4 全新制作，本轮不复用旧素材。

| 项目 | 实施基线 |
| --- | --- |
| 颜色 | 背景 `#151718`，表面 `#222725`，文字 `#F4F6F5`，次级文字 `#AEB8B3`，强调暗红 `#8F2435`，成功冷绿 `#76C4A3`，警示 `#E78085`；完成页面时复查实际对比度 |
| 字体 | 中文系统无衬线优先；正文 16px、操作 16px、区标题 24px；固定字号，不按视口宽度缩放，字距 0 |
| 间距 | 4、8、12、16、24、32px；触控至少 44px，相邻操作至少 8px |
| 座位 | 360px 两列，宽手机可三列，桌面最多四列；固定网格轨道，目标块最小高度 88px，昵称允许换行 |
| 图片 | 本人角色插画建议 3:4 固定比例；统一牌背占同等尺寸，不因角色更换导致内容跳动 |
| 组件 | 段选用于模式；数字步进用于人数；单选用于唯一目标；工具使用图标及可访问名称；明确命令才使用文字按钮 |
| 圆角 | 座位等重复项目 6px；页面区段不包装成浮动卡片，不嵌套卡片 |
| 动效 | 以 120 至 180ms 状态过渡为主；减少动态设置下移除翻牌与位移动效，反馈仍完整 |
| 桌面 | 主要内容最大 1040px，玩家任务仍在主要区域；主持维护为次级区域，不扩展成全知大屏 |

图标支持键盘焦点、触控可见名称及悬浮提示。选中同时使用轮廓、勾选与文字，不仅变色；出局与禁用也有语义标签。公开提示可使用克制的 live region，私密身份、查验、刀口不自动进入朗读或通知。

## 实现与验收顺序

先完成入口、大厅和身份遮蔽，再接夜晚目标与狼人协作，然后实现同机主持、白天录入、猎人反应与复盘，最后处理完整恢复和素材播放器。组件职责为 RoomScreen、SeatGrid、PrivacyPanel、ActionForm、WolfConsensus、HostDrawer、VoteDraft、RecapTimeline 与 NarrationController；它们只展示过滤后的视图，不接收内部 Game。

阶段 3 验收需真实页面完成 8 人与 12 人一局及下一局，验证长昵称、大字、360、390、768、1440px、键盘与减少动态。多浏览器上下文核对网络响应而不只核对隐藏文字；真机声音、素材加载和完整故障验收仍见阶段 4 与 5。
