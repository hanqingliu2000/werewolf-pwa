# 01 产品需求

更新：2026-10-07。状态：范围已确认，规则、保存权限及文字网页已验收；正式声音与线上产品仍未完成。

产品定位见 [00](00-product-vision.md)，具体规则分支见 [02](02-rules-and-decisions.md)。本文件定义能力与用户结果，不固定路由、数据库或组件实现。

## 用户任务

- 组织者：快速安排一桌人，自己也参与游戏。
- 玩家：知道自己的身份和当前行动，准确选择座位目标。
- 房主手机：在本人参与游戏的同时，让所有人听到同一套公共指令与公告。
- 出局玩家：继续看公共进度，局后参与复盘，不获得新的秘密行动信息。

## P0：首版必需

| 编号 | 能力 | 可观察的验收结果 |
| --- | --- | --- |
| P0-01 | 创建房间与选择候选板子 | 支持 8 至 12 人、六角色及受限自定义；开局前明确配比与胜负；未经实测不标为已验证推荐 |
| P0-02 | 邀请与加入 | 支持链接、房间码及二维码；无需账号或安装；重复加入不产生额外座位 |
| P0-03 | 座位与准备 | 每人有稳定座位号和昵称；可在开局前整理席位；人数正确且玩家准备后才开始 |
| P0-04 | 秘密发牌 | 每局重新随机分配；本人查看并遮蔽身份；公开内容和房主维护视角不包含身份表 |
| P0-05 | 夜晚行动 | 所选板子中的角色按确认的规则行动；目标、次数、自救、放弃等条件明确；显示私密提交回执 |
| P0-06 | 狼人协作 | 存活狼人私下看到队友和目标提议，能够达成并确认共同目标 |
| P0-07 | 公共主持 | 仅房主手机发声；开局试音；普通窗口 30 秒、狼人 45 秒；提前提交不提前闭窗 |
| P0-08 | 统一结算 | 死亡、猎人反应及胜负按固定顺序执行；白天出局也能触发合法反应 |
| P0-09 | 白天支持 | 线下处理发言和投票；房主选择、确认待发布、再发布结果；发布前可改，发布后不可撤销 |
| P0-10 | 容错与恢复 | 刷新恢复原身份，已提交行动不丢失或重复生效；短时断线能恢复 |
| P0-11 | 暂停与原设备恢复 | 房主出局保留组织权限；失联暂停并等待原设备；不接管、不代选；恢复窗口延长 30 秒 |
| P0-12 | 声音降级 | 播放受阻有明确恢复入口；可选择文字主持；游戏操作不会被音频错误吞掉 |
| P0-13 | 结束与下一局 | 本局参与者可看全部身份和逐夜复盘；保留席位重开，重新发牌并重置资源；严重误录可明确中止重开 |
| P0-14 | 全新视觉与语音 | 暗黑奇幻插画、统一牌背与全套清晰中文男声指令；旧素材仅参考，不作为新发布资源 |

## P1：首版稳定后增强

六角色均进入首版实现范围。候选预设与自定义必须通过配置和规则测试；配比平衡仍需实测，不能因一局仿真通过而把所有人数标为已验证推荐。

- 保存常用板子；逐步增加经实测的推荐人数与配比。
- 可选讨论计时和更丰富的复盘表达。
- 已有新角色插画、日夜视觉和动效的进一步打磨，以及可选环境音。
- 添加到主屏幕等网页安装体验。

P1 功能不能替代 P0 的保密、规则正确性和恢复能力。

## 不在范围内

原生 App、应用商店分发、全局离线运行、远程语音房、陌生人匹配、复杂社交、付费体系、扩展角色、自由编写规则、额外公共设备、主持接管、换设备身份恢复和网页逐人投票。

## 重要体验约束

- 入场、身份查看、行动、提交回执构成短路径；设置和历史不挤占行动区域。
- 房主不靠查看秘密信息处理等待或断线。
- 失联或未行动不会自动随机选人、消耗药剂或改变阵营结果。
- 普通玩家手机不播放角色专属声音或震动提醒。
- 跨设备一致性覆盖规则、信息可见性、行动结果和恢复行为，而不仅是颜色和排版。

## 初步测量目标

建议把单个新玩家从邀请到就绪控制在 30 至 60 秒，整桌准备在 2 至 3 分钟内完成。记录正常白天录入之外的维护次数、卡住时间、误点次数和再次开局意愿。这些目标必须通过线下实测验证。
