# 26 公开网站必要安全防护与发布

更新：2026-10-09。范围为不改变正常使用的服务端必要防护，以及将最近的界面与行动回执更新同步到现有正式站。没有新增登录、验证码、身份验证、用户验证模块或付费安全服务。

## 防护范围

- 继续使用参数化SQL。仅固定允许的私有schema名称进入查询标识符；昵称、房间号、回执键等数据通过绑定参数传递，不添加会误伤正常昵称的SQL关键词黑名单。
- API路径、房间号、请求类型、JSON结构、配置与16KiB请求大小在数据库访问前检查。非法路径、SQL形状的房间号和明显错误的请求不会进入数据库限流或房间读取。
- 保留原有数据库限流、会话权限、房主/角色权限、同源写入校验及Secure/HttpOnly/Strict Cookie。增加实例内的数据库前减压过滤：同平台IP每分钟2400次API请求，健康检查单独每分钟60次；可更换Cookie但不能更换该实例识别的平台IP。模拟12人共享IP的一分钟1800次API预算检查未触发新增限制，原有业务配额仍生效，没有额外操作步骤。
- IP只从Vercel的平台请求头读取，不接受客户端的普通转发头作为可信身份；只存摘要，最多2048个分钟窗口，不记录IP、Cookie或角色数据。本地开发不启用平台IP限流。实例内过滤不是跨实例的分布式DDoS防护；原有持久化业务配额和平台基础防护继续保留。
- 全站增加或统一nosniff、SAMEORIGIN和no-referrer响应头。不设置影响音频自动播放的限制，不引入可能影响现有脚本或素材的复杂CSP。

## 数据库核验

现有Supabase项目的preview/prod六张内部表均启用RLS；anon与authenticated没有schema使用权或表读取权。两个应用账号均不是超级用户，没有建库、创建角色或绕过RLS权限；数据库仅通过服务端最小权限账号和校验TLS证书的连接访问。安全advisor无发现。本次无需迁移或修改现有数据库权限。

Supabase保持Free，Vercel保持Hobby且没有试用。沿用现有资源，不启用有计量费用的WAF限流规则，也不新建或升级资源。

## 本地验收

类型检查、lint、270项规则/服务/安全回归及生产构建通过。新增检查包括SQLite/PostgreSQL中SQL形状的昵称和查询键按字面值处理、非法请求不调用数据库计数器、健康检查高频拒绝不打开存储、Cookie轮换、预算过期、内存上限及共享Wi-Fi访问。

Chromium与WebKit的10项生产构建局部回归通过，包含入口、六身份牌、五角色8/12人单屏行动及私密遮蔽；4项临时评审浏览器检查通过，SAMEORIGIN未阻断同源评审画布与14个示例。没有运行完整局。

生产部署先保持现有网址不变，候选通过接口和短程浏览器检查后才手动提升。发布版本、部署编号及正式站检查结果在完成后记录于下方；本次不执行新的完整对局或真实手机音频验收。
