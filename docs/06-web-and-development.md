# 06 网页与开发原则

更新：2026-10-06。状态：技术方案准备原则，不是框架、API 或数据库设计。

## 已确定的平台边界

只开发网页版。iPhone、Android 手机和桌面浏览器使用同一产品，原生 App、WebView 壳、原生音频插件及应用商店分发均不在范围内。无需为当前产品申请 Apple 开发者项目。

手机优先验证 iOS Safari 与 Android Chrome，桌面浏览器承担可选公共展示。具体支持版本在开发前根据实际测试设备确定。安装到主屏幕不是入场条件，PWA 增强后续单独评估。

## 浏览器声音约定

有声音的自动播放可能被阻止，不同浏览器的策略也不同。即使曾有用户交互，后续播放也需要处理失败；不能仅凭点击某个按钮就永久标记“播放已解锁”。这些边界见 [MDN 自动播放指南](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay)。

首版产品约定：

1. 公共设备在大厅主动选择语音主持并完成实际试音，才能开始该模式。
2. 普通玩家默认静音，不要求所有人启用音频。
3. 所有公共指令有等价文字；支持主动选择文字主持。
4. 播放失败、中断与声音资源缺失都有明确状态，允许恢复当前有效指令。
5. 音频恢复操作不抢占玩家行动，不重放过期阶段，不自动重复结算。

后台页面可能受到计时和资源调度限制，详见 [MDN 页面可见性说明](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)。首版要求公共主持网页保持前台，不承诺锁屏、切后台或长时间休眠后仍持续主持。恢复前台时重新同步对局并确认声音状态。

## 核心职责

| 职责 | 要解决的问题 |
| --- | --- |
| 规则核心 | 对同一规则版本与行动集合得出唯一结果，不依赖 UI 或声音 |
| 对局协调 | 管理公开窗口、准备、暂停、反应与判胜，处理重复请求和过期操作 |
| 信息视角 | 按权限提供公共、本人和角色协作信息，房主不获得全知数据 |
| 网页呈现 | 让用户完成当前任务，显示已确认结果和恢复状态 |
| 公共声音 | 顺序播报已确认的公共指令，处理启用、失败、中断和恢复 |
| 保存与恢复 | 保存对局事实，保证刷新、短时断线及服务重启后可继续 |

规则只有一个权威来源，不能让网页、服务器和数据库函数分别维护不同版本的结算。房主页面关闭不会丢失对局事实；播放器也不能直接决定赢家。

## 技术选型约束

- 根据规则与浏览器实测选择方案，优先减少首版维护成本。
- 规则、权限与保存应易于独立验证；使用可靠的随机源分配身份。
- 运行时校验开局配置，重复提交不重复生效，过期行动不会进入新窗口。
- 数据自身符合信息边界，不先把全部身份发送给网页再隐藏。
- 同一局固定规则与必要内容版本，部署或缓存更新不能中途改变玩法。
- 记录足够的公共结果与私密事实用于恢复，但不在公开日志中记录身份、凭据或查验内容。

前端框架、同步方式、服务器、数据库、托管与详细接口均未选定。旧 Next.js、Supabase、Capacitor 和 RPC 仅是历史参考，不自动迁入新基线。

## 进入实现前的交付

在关键规则与交互确认后，形成简短技术决策：说明选型理由、数据与权限边界、恢复策略、浏览器声音验证和实施次序，再补足必要的接口及数据设计。

本轮清理不操作旧云数据库、线上部署或已安装应用。后续新版本需先使用独立测试环境，确认发布范围后再决定如何替换旧服务。
