# 21 单屏行动界面与完整流程验收

更新：2026-10-08。目标：守卫、狼人、女巫、预言家和猎人行动时，目标与主要操作在当前屏幕内同时可见，不再只保证确认按钮常驻。规则、时长、语音素材和人工遗言安排保持不变。

## 行动界面

行动界面分为本人身份与倒计时、角色状态、全部座位目标及确认区。竖屏使用三列目标，短竖屏改为四列；横屏采用角色状态在左、四列目标在右的布局。座位号作为主要标签，触控按钮至少44×44px，字号固定，不随视口宽度缩放。

女巫的药剂余量、狼刀目标及解药/毒药/不用药选项同时保留；狼人显示全部存活队友的提议与确认状态，横屏采用单列状态表，避免文字挤压。守卫保留上一夜目标提示，非法目标和出局玩家仍禁用；猎人仍只能在合法公告后的反应窗口选择其他存活目标或放弃。

长昵称在目标中单行省略，座位号始终完整；原始全名保留在可访问名称、悬浮标题及可点击、可键盘打开的完整名单中。角色规则和既有查验记录放在次级私密浮层中，不占主行动区。切后台、关闭或阶段变化仍遮蔽所有私密内容。

单屏保证针对下面已测的默认字号尺寸。极小视口、强制大字或打开详情时保留滚动能力，不隐藏操作或禁止浏览器缩放；未宣称所有无界文字放大组合均可一屏显示。

## 布局矩阵

`flow-fixes.spec.ts` 针对8/12人、全部五种行动角色，逐项检查以下尺寸：

| 竖屏与桌面 | 横屏 |
| --- | --- |
| 320×568、360×560、360×640、390×844、768×900、1440×900 | 640×320、740×360、844×390 |

每个浏览器包含90个角色/人数/尺寸组合。断言不仅检查确认按钮，还检查所有8/12个目标均在目标区域和视口内、主操作区没有滚动溢出、全部按钮达到44px、狼队文字不重叠、本人位图实际加载。长昵称完整名单和键盘选择可用；死亡猎人自身目标保留出局状态并禁用。

首次截图发现横屏狼队状态文字挤压，已改为单列并增加文字范围宽度断言。原自动弹窗、狼人协商等待、播报回执重试与白天改选防误发布保持通过。

## 完整流程

Chromium和WebKit分别完成8人、12人独立浏览器会话文字对局及下一局，共4项完整流程通过。使用真实页面和本地服务，随机发牌，确认身份，逐角色行动，黎明公告，合法猎人射击/放弃，白天发布，胜负，复盘和重开；12人用例包含房主夜晚出局后继续主持。

这些是功能回归，不是独立agent策略试玩。仅在隔离的本地SQLite测试库中压缩已经提交完毕的等待窗口，不改变生产计时；不代表按真实时长的完整语音局或现场聚会节奏验收。

## 本机入口修正

完整流程初次执行在建房入口失败：安装版本的NextURL把127.0.0.1和IPv6回环地址规范化为localhost，原同源判断与显式配置的本机Origin不一致。

修正只兼容已知回环主机，并继续比较协议、端口及配置的Origin。外部网址仍严格同源，不能用另一个已配置部署域名代替当前请求来源；跨站/同站非同源请求、错误端口、错误协议和未配置声明仍被拒绝。错误信息只给类别，不回显网址、请求头或凭据。新增针对规范化和拒绝路径的安全用例，完整文字流程复测通过。
