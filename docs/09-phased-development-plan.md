# 09 分阶段开发计划

更新：2026-10-06。状态：实施基线已制定，应用开发尚未开始。

本计划把已确认的产品选择转成可逐阶段交付的网页版重构任务。先完成本机开发与验收，再准备新后端、备份并清空旧游戏数据、替换原网址，最后以每名 agent 扮演一名玩家的方式进行线上仿真。不能把文档完成、文件存在或仿真通过误写成真实手机音频已经验收。

## 已确认的产品范围

| 项目 | 首版决定 |
| --- | --- |
| 场景与平台 | 8 至 12 人的熟人线下聚会，手机优先的响应式网页版；不做原生 App、远程语音房或单手机传递 |
| 角色与配置 | 狼人、预言家、女巫、守卫、猎人、平民全部进入首版规则范围；人数预设和受限自定义并存 |
| 胜负 | 默认屠边，人数规则可选，开局二选一；完整死亡结算与合法猎人反应结束后判胜；全员出局平局 |
| 公共主持 | 仅房主的玩家手机播音，不提供额外播报设备或主持接管；出局不解除房主权限 |
| 夜晚窗口 | 普通角色 30 秒，狼人 45 秒；开眼语音结束后开始计时；提前完成不提前闭窗 |
| 超时与恢复 | 未行动或狼人未达成一致时暂停，不代选、不自动放弃；房主恢复时延长当前窗口 30 秒 |
| 行动确认 | 常规行动确认后锁定；狼人个人选择为可修改提议，最终共同确认才锁定 |
| 白天 | 讨论、警长、平票、遗言和投票在线下处理；房主录入、确认待发布，再发布结果 |
| 误录 | 发布前可更正，发布后不可撤销；严重误录可由房主明确终止本局并重开 |
| 身份恢复 | 仅原浏览器刷新和短时断线恢复；不支持换手机恢复或离线接管 |
| 出局与复盘 | 普通角色出局不自动公开身份，猎人例外；局后向本局参与者公开全部身份和逐夜行动 |
| 视觉与声音 | 暗黑奇幻沉浸风，全新美术、全套新中文主持音频，清晰克制的男声；不克隆真人 |
| 上线 | 原网址配全新 Supabase 后端；旧游戏数据不迁移，备份后于新版上线前清空 |
| 成本 | 新后端仅免费，不自动升级；组织为 barryliu's projects，当前创建成本查询为 0 美元/月，执行前必须重新核验 |

完整角色规则以 [02 规则与决策](02-rules-and-decisions.md) 为准，页面信息边界以 [03](03-gameplay-and-privacy.md) 为准。原参考素材不进入新版本发布资源。

## 技术基线与实施默认值

以下是实施默认值，不是额外声称已经经过用户实测的产品结论：

- 新应用位于 `web/`，使用 Next.js、React、TypeScript。安装前核查官方稳定版本，精确锁定依赖和锁文件；运行时使用本机已验证的 Node.js 24 系列。
- 本地使用 SQLite 持久化，线上使用新 Supabase PostgreSQL 项目，区域为 `us-east-1`。本地 `node:sqlite` 接口仍有实验性标记，需要锁定运行时并覆盖重启和并发测试；线上不使用 SQLite。
- 规则只在服务端 TypeScript 核心实现一次。数据库保存对局事实并进行原子条件更新，不重复实现女巫、守卫、猎人和判胜规则。
- 每个房间保存版本化的权威状态，包括当前局、席位、已确认动作、资源、窗口、公开事件和复盘。条件写入失败时重新加载并检查请求，而不是覆盖较新的状态。
- 前台每秒同步一次；后台降至每 5 秒一次。房主每 3 秒心跳一次，连续 10 秒无有效心跳即暂停公开推进。浏览器主动离开前台或音频失败时也请求暂停，服务端心跳作为兜底。
- 会话凭据仅用于原浏览器恢复，服务端保存验证材料，凭据不进入公开视图、地址栏、日志、截图或 Git。所有私密响应禁止共享缓存。
- 房间和复盘默认在最后一次有效游戏操作后保留 24 小时；纯轮询、心跳不延长保留期。到期拒绝继续操作并清理数据；新局与旧局使用不同对局编号。
- 房主结束本局是明确确认的终止操作，复盘标记为中止，不伪造胜负。重开保留席位，重置角色、药剂、查验、守护限制、共同确认及语音队列。
- 首版不新增环境音、复杂 3D、讨论计时、网页逐人投票、换设备恢复、主持接管或公共投屏设备。

### 最小接口与类型契约

| 能力 | 请求或类型重点 | 可返回的内容 |
| --- | --- | --- |
| 建房与加入 | 人数、规则配置、昵称和房间码；加入只允许大厅且有空位 | 当前浏览器的会话与合法房间视图，不返回全员身份 |
| 席位与准备 | 本人准备；房主仅在开局前管理席位和配置 | 公开席位、准备和规则，不显示秘密动作等待者 |
| 获取对局 | `PublicRoomView`、`PlayerPrivateView`、按角色授权的 `WolfTeamView` | 公开信息、本人私密信息、合法狼队协作信息 |
| 提交行动 | `Command` 携带 `gameId`、`windowId`、`requestId` 和经过校验的目标 | 本人提交回执；查验结果仅返回给本人 |
| 房主控制 | 开始、暂停、恢复、声音状态、白天草案与发布、终止和重开 | 不泄密的公开变化，组织权限不提供全知数据 |
| 局后复盘 | `GameRecap` 固定参与者、规则和内容版本 | 对应局参与者可见；新加入者不能读取未参与的旧局秘密 |

`RuleConfig`、权威 `RoomState` 与视图类型必须分离。存储并发版本不直接作为公开进度输出，避免泄露私密动作数量。重复请求返回已确认结果；过期局或窗口的请求不进入新状态。线上数据启用行级安全并撤销浏览器直读权限，服务端凭据不能成为浏览器公开环境变量。

## 阶段 1 新应用与规则核心

交付可独立运行测试的新应用骨架，以及不依赖界面、音频或数据库的规则核心。

- 校验 8 至 12 人、角色总数、神职不重复、狼人数量上限，以及狼人、平民和神职均存在的配置。
- 用可靠随机源发牌，不能与名字、席位顺序或加入顺序固定对应。预设作为实测候选，不宣传已经证明平衡。
- 实现合法目标、确认锁定、狼队共同目标、夜晚死亡批次、猎人资格与放弃、两种胜负方式和中止重开。
- 狼人更改个人提议时清除旧共同确认；存在不同提议时不能锁定击杀。全体共同空刀与未行动不同。
- 已配置但死亡或耗尽资源的角色不要求真实行动，但保留同样长的公开呼叫窗口。猎人没有常规夜间目标动作。
- 夜晚顺序固定为守卫、狼人、女巫、预言家；未配置的角色可跳过。毒药禁枪条件不能被单一“主要死因”覆盖。

验收：规则矩阵逐项通过；同一动作集合的结算不受网络到达顺序影响；最后神职的合法猎人反应不被提前判胜截断；没有非法消耗和无结果的必经分支。

## 阶段 2 对局事实与权限接口

交付本地持久化、原浏览器会话、角色过滤视图，以及与线上相同语义的原子更新契约。

- 建房、加入、准备、行动及房主控制均在服务端验证身份、房间、阶段和权限。
- 保存事实后才返回已接受回执；本地不能用模块内存映射作为事实来源，刷新或服务重启后仍可恢复。
- 并发写入采用版本比较，动作使用请求编号去重；多个狼人同时确认、多个玩家争最后席位和重复发布都不能产生双重效果。
- 服务端掌握截止时间、暂停状态和恢复剩余时间，客户端倒计时只是显示。暂停不推进窗口，也不因重试改变动作。
- 房主出局仍能暂停、录入和播音；失联后不转交权限。丢失原浏览器会话时不能让房主查看或重置别人的秘密身份。
- 完成到期拒绝访问与数据清理，限制建房、加入和动作请求频率；不把秘密状态或凭据写入公开错误信息。

验收：无身份冒用、跨房间访问、房主越权或秘密状态直读；重试、冲突和重启恢复通过；公开响应不泄露私密动作数量或等待者身份。

## 阶段 3 完整网页版体验

交付入口、大厅、私密身份、夜晚行动、狼队协作、房主控制、黎明公告、猎人反应、白天录入、复盘和下一局。

- 第一屏就是创建或加入的实际工具，不做营销落地页；玩家行动占手机首屏，维护设置放在次级入口。
- 座位号稳定且用于所有选择与公告；长昵称换行，触控目标至少 44px，选中、死亡与禁用不只靠颜色表示。
- 身份默认遮蔽，恢复前台或刷新时重新遮蔽；待机背景、牌背、声音和亮度策略不因角色而不同。
- 房主在同一网页中完成自己的秘密行动和主持维护，不需要第二设备，不让播音设置压住个人行动。
- 常规确认后不可改；狼队显示提议与共同确认的区别。加载、已接受、失败和过期状态清楚区分。
- 白天结果先保存私有草案，再确认待发布，最后明确发布；发布才改变公开存活状态并揭示猎人身份。
- 猎人死亡公告公开身份，无论是否中毒或放弃；无毒且有资格时本人选目标或放弃，被毒则无开枪选项。夜晚不得提前公开猎人。
- 局后展示身份和逐夜记录；未结束时不得通过复盘入口读到秘密。下一局关闭旧局行动入口并清理旧语音队列。

验收：通过真实页面操作完成一局与下一局；普通玩家只能看到自己的秘密；房主兼玩家路径无额外设备依赖；更正不会回收已经公开的秘密。

## 阶段 4 全新素材与公共声音

交付统一的暗黑奇幻角色美术、公共场景、牌背、完整脚本、可重复生成的男声音频，以及与规则窗口协同的播放器。

- 生成六角色插画、统一牌背和必要场景位图；文字独立排版，不烘焙在插画里。采用炭黑基底、暗红和冷绿辅助色，避免整站只有一种色相。
- 私密角色插画只出现在本人允许查看的场景；公共待机不展示角色专属背景。动效克制并支持减少动态效果。
- 新主持脚本覆盖试音、开闭眼、暂停、恢复、黎明名单、猎人身份与反应、白天结果、胜负、中止和重开。
- 本地使用 `Qwen3-TTS-12Hz-0.6B-CustomVoice` 的中文男声 `Uncle_Fu`，先验证样音，再批量生成静态文件；不在服务器实时托管 TTS，不使用真人克隆或未获确认的付费接口。
- 保持同一声线、清楚的语速和一致音量。用座位号而非昵称播报，准备 1 至 12 号数字与可组合句式；不生成私人查验、刀口或狼队信息的公共声音。
- 所有资源记录来源、许可、文本版本、模型与生成参数、文件校验值和验收状态；旧 `materials/` 仅供参考，不复制成正式资源。
- 只有房主手机播放。大厅真实试音后启用语音；开眼播报完成才开放计时窗口。失败、中断、资源缺失或离开前台进入可恢复暂停。
- 语音失败可明确转文字主持；恢复只处理当前有效指令，不重放过期队列，不重复结算，也不吞掉个人行动点击。

验收：全部脚本有对应音频或经过验证的组合路径；素材可加载，长短语句不截断、不爆音；角色与死因不在公告前泄露。音源或环境不达标时记录阻碍并停止素材发布，不静默替换为付费服务或旧音频。

## 阶段 5 本机验收

交付可复现的测试结果与桌面、手机尺寸截图。启动本地开发服务并提供实际可访问地址；端口冲突时改用空闲端口。

| 类别 | 必测范围 | 通过标准 |
| --- | --- | --- |
| 规则 | 自救、药剂、空刀、连守、守救、复合毒杀、猎人、两种胜负与平局 | 合法动作生效一次；非法动作不消耗资源；完整反应后判胜 |
| 接口 | 同时加入、重复提交、共同确认变更、过期动作、越权与跨房间访问 | 无覆盖、重复效果或秘密数据外泄 |
| 恢复 | 玩家刷新、服务重启、房主离线、到期、音频中断 | 恢复原事实，不重发身份、不接管、不补播过期声音 |
| 白天与重开 | 草案改错、发布后误录、猎人放弃、复盘权限、下一局 | 发布前可改，发布后不可回滚；新旧局秘密与资源隔离 |
| 界面 | 360、390、768、1440px 宽度，长昵称、大字、触控和减少动态效果 | 无横向溢出、文字遮挡或控制重叠，所有素材实际呈现 |
| 浏览器 | Chromium、WebKit 的多人独立会话与播放状态 | 页面流程与状态正确；不得据此声称真实 iPhone 扬声器已验收 |

规则测试、接口测试、完整浏览器流程、静态检查和生产构建全部通过后才进入云端准备。真实 iOS Safari、Android Chrome 的音量与自动播放体验仍需补充实机验收；缺少设备时明确记为未验证。

## 阶段 6 新后端与旧网址替换

所有云端操作必须在本机验收后执行，且不能跳过旧数据备份与范围确认。

1. 重新查询已选组织的创建成本和额度，按平台要求确认费用；只有零增费条件满足才创建新的 `werewolf-web-v2` 后端，不能自动升级、付费或改用别的组织。
2. 配置新数据库、权限和仅服务端可用的凭据；验证匿名客户端不能直读秘密状态，验证线上条件写入与本地契约一致。凭据不进入 Git、浏览器代码或公开日志。
3. 恢复旧后端并核查真实云端结构。规划时旧项目为非活动状态且表查询超时，归档里的四张表不能证明云端当前只有这些数据；若恢复需要额外费用或无法取得访问权限，先停在此门槛。
4. 识别属于旧狼人杀的 `rooms`、`players`、`night_actions`、`events` 数据及关联关系；遇到其他应用表、未知依赖或范围不明时停止，不使用无边界的级联清空。
5. 备份受影响数据和必要结构到被忽略、权限受限的本地目录，记录校验值和行数，并在隔离环境验证可恢复。备份包含旧会话信息时不得提交或上传到公开仓库。
6. 在事务内仅删除已核实的旧游戏数据，验证目标行已清空且其他应用未受影响。不删除整个旧项目、旧表结构、函数或本地归档。
7. 保留原 Vercel 部署标识，配置新后端并替换原网站 `https://werewolf-pwa.vercel.app`；核查部署后的页面、接口、素材和权限，再进入线上仿真。

本阶段停止条件：费用不符、额度不足、账号权限缺失、备份不可恢复、数据范围不明或新后端权限测试失败。此时仍可保留已通过的本机版本，但不得擅自跳过清空门槛发布。

回退使用保存的旧部署与经过验证的数据备份。只回退前端不能恢复已清空的旧数据，也不能保证回退到旧规则后仍可读取新后端；回退时必须同时处理前端指向与所需旧数据恢复。

## 阶段 7 逐玩家 agent 线上仿真

交付一局 12 人全角色对局的试玩报告，以及重开检查。每位玩家由一个独立 agent 扮演，其中一位同时承担房主，不增加新的用户聊天任务或额外公共设备。

- 每位玩家有独立浏览器会话和 Cookie；使用真实页面、随机发牌和普通玩家接口，不使用线上强制分配角色或跳过结算的测试后门。
- 玩家 agent 只读取本人页面及合法队内信息，不读取数据库、服务端文件、其他会话或全员身份。观察者报告可以汇总错误，但不能把秘密信息提供给玩家决策。
- 公共消息通道模拟线下发言和投票，不把这个通道增加为产品的远程聊天功能；狼人只在合法队内协作。房主 agent 根据公开结果录入并发布白天淘汰。
- 按真实 30 秒、45 秒窗口行动；需要暂停时走正式恢复流程，不修改生产计时规则来让仿真更容易通过。
- 并发额度不足时保存每位玩家的独立上下文，分批唤醒同一玩家 agent；不把多位玩家合并成一个全知代理，不以普通自动化脚本冒充已经完成 agent 试玩。
- 完成入场、准备、身份确认、夜晚、黎明、白天、合法猎人反应、胜负、复盘和重开。随机对局未覆盖的规则分支由阶段 5 的确定性测试证明，不能伪称一局随机试玩覆盖所有分支。
- 仿真出现问题时保存证据，修复后重跑受影响用例并重新完成对局；无法完成时明确报告失败节点。

报告应包含应用与规则版本、部署标识、玩家数量、公共讨论记录、关键截图、观察到的胜负与复盘一致性、问题与复测结果，以及没有验证的真机音频行为。私密日志若包含完整角色或会话材料，仅本地受限保存，不推送到公开仓库。

## 阶段记录与后续验收

每阶段记录进入条件、完成时间、代码或部署版本、测试结果、未验证项和下一阶段门槛。阶段 7 通过表示线上仿真通过，不表示所有人数的平衡或所有手机音频策略都已验证。

真实聚会后补充 iOS Safari 与 Android Chrome 的声音、操作隐私和维护负担测试，再把经过验证的候选配比升级为推荐板子。后续环境音、安装增强和更多规则变体不得替代首版保密与正确性。
