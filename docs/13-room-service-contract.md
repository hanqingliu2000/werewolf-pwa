# 13 房间保存与接口契约

更新：2026-10-07。本契约对应本地保存、网页与主持播放器，供后续云端适配使用。权威事实只在服务端，网页不能读取内部 Room 或 Game。

## 数据分层

`src/game/` 是唯一规则核心；`src/server/service.ts` 管理大厅、原浏览器身份、协调和原子请求；`views.ts` 负责信息投影；`http.ts` 处理请求防护与 Cookie。Next.js 路由只装配存储和服务，不实现角色规则。

SQLite 使用房间、请求回执和限额三个表。房间保存版本化 JSON 快照；内部并发版本仅用于条件更新，不返回客户端。档案记录参与者的会话摘要快照，后来入场或成为房主都不能获得旧局秘密权限。

服务和HTTP调用链已完整异步等待读写，RoomStore兼容本地SQLite即时结果与PostgreSQL Promise；两种适配复用保存契约测试。Vercel只使用新Supabase私有schema，不用模块内存或临时SQLite代替数据库事实。原子条件写入与请求回执是同一次事务，数据库只承担保存、比较版本、去重、限流和到期清理，不另写一套角色结算函数。运行配置及发布记录见 [19](19-cloud-deployment.md)。

## 会话

调用 `POST /api/v2/session`，JSON 请求体为 `{}`。凭据只通过 `Set-Cookie` 返回，JSON 为 `{ "ok": true }`。有效 Cookie 初始化时保持原值，失效或不存在时生成新值。

其他接口必须携带 Cookie，写请求必须有准确的 `Origin` 和 `application/json` 类型。开发默认只接受 localhost 或 127.0.0.1；非本机写请求必须显式配置 `WEREWOLF_ORIGIN`。HTTPS 配置会启用 Secure Cookie，不接收浏览器提供的 `actorId`、时间、角色队列或随机种子。

原浏览器持有的同一凭据可以绑定不同房间，但每次读取和操作仍验证该房间资格。房间号、昵称、座位号及玩家 ID 都不是凭据。会话不能用于换设备认领或主持接管。

## HTTP 入口

以下路径全部以 `/api/v2` 开头。旧 `/api/rooms` 不恢复。

| 方法与路径 | 内容 | 权限 |
| --- | --- | --- |
| `POST /session` | 初始化 Cookie | 同源、限频 |
| `POST /rooms` | `requestId`、`name`、`config` | 有会话；返回房间编号与回执 |
| `GET /rooms/:room/invitation` | 配置、当前大厅编号、占用座位号、是否已开始 | 有会话及房间号；没有身份、玩家姓名或秘密事实 |
| `POST /rooms/:room/join` | `requestId`、`epochId`、`name` | 未开始、同名和容量校验；同会话已有席位则恢复 |
| `GET /rooms/:room` | 公共阶段、窗口、配置、已公告名单、事件及本人的席位标识 | 当前成员 |
| `GET /rooms/:room/private` | 本人身份、行动确认状态、已接受动作、合法任务及本人角色记录 | 当前成员；活狼才获当前协作信息 |
| `GET /rooms/:room/host` | 组织控制、当前公开指令、私有白天草案 | 当前房主，即使已出局 |
| `POST /rooms/:room/commands` | 有编号和上下文的操作 | 当前成员，逐命令验证阶段与权限 |
| `POST /rooms/:room/heartbeat` | `foreground`、`audioReady` | 仅原房主；不是公开成员在线列表 |
| `GET /rooms/:room/recaps` | 本人参加过且尚保留的已结束对局列表 | 当前成员或合法旧档案参与者 |
| `GET /rooms/:room/recaps/:game` | 该局身份、逐夜动作、公开事件和结果 | 已结束，且会话参加过该局 |

所有响应包含私密禁止缓存策略，错误也不缓存。本人视图和房主视图不能混成公共响应；客户端关闭私密面板时无需继续取回秘密。

本人及房主响应同时带 `epochId` 与 `windowId`，用于和公共视图配对；它们是公共上下文，不是内部写版本或秘密动作计数。页面不能把不同窗口的响应合并显示。

本人投影可增加只读 `actionResult: { kind, targetId, nightNo }`，没有已确认结果时不返回。守卫、女巫、预言家沿用当前夜已接受动作的类型；狼队全体确认并锁定后才返回参与狼人的 `kill`，不是个人提议；猎人从本局本人公开反应事件派生 `shot`，null表示放弃，并保留该事件自己的夜号。白天猎人反应后可能立即开始下一夜，其已完成回执仍保留至本局结束或重开。原 `acceptedAction` 字段和命令输入不变。结果从已有快照派生，不增加另一套规则、持久化字段或写入；不会包含最终夜间死亡、他人查验或药剂知识，也不进入公共/房主投影。预言家页面按 `nightNo` 与 `targetId` 匹配本人已有报告，不使用其他夜的旧阵营结果。

## 命令上下文

```json
{
  "requestId": "客户端新生成的 UUID",
  "epochId": "公共响应里的当前大厅或对局 UUID",
  "windowId": "公共响应里的当前 windowId",
  "operation": { "type": "guard", "targetId": null }
}
```

示例中的占位文字不是合法 UUID。实际客户端用 `crypto.randomUUID()`，上下文从最近同步响应取得，不自行构造。`targetId: null` 是明确放弃，不是未选择。

成功回执为 `accepted`、`requestId`、`roomId`、`epochId`、`flowId`。回执表示该请求已保存，不代表返回了当前完整视图；重复请求可能返回历史回执，页面随后同步最新状态。不能仅依据回执推进画面或声音。

| 命令 | 额外字段 | 权限与约束 |
| --- | --- | --- |
| `ready` | `ready` 布尔值 | 大厅本人 |
| `seat` | `seat` 数字 | 大厅本人，空位及容量校验 |
| `rename` | `name` | 大厅本人，去首尾空白、NFC、48 字符以内、拒绝控制字符及重名 |
| `leave` | 无 | 大厅非房主 |
| `configure` | `config` | 大厅房主，清除全员准备 |
| `kick` | `playerId` | 大厅房主，不可移除本人 |
| `start` | 无 | 房主，满员且全员准备，随机发牌 |
| `acknowledge` | 无 | 已废弃；仅兼容旧客户端发牌阶段的迟到请求，成员和局/窗口校验不变，不记录身份确认 |
| `begin_night` | 无 | 房主，发牌播报完成且主持可用，不等待全员查看或确认 |
| `cue_ack` | 语音模式必需 `cueId`，等于当前公开 `windowId`，及当前音频 `version` | 房主，当前公开指令；映射开窗、闭眼后推进或黎明发布；文字模式保持原手动协议 |
| `announcement_done` | `cueId` 等于待播公告编号；语音模式另需当前音频 `version` | 房主，确认已公开的名单、猎人、胜负或新大厅公告完成；不重复结算 |
| `narration_mode` | `mode` 为 text 或 voice，`version` 为当前脚本版本 host-zh-v3，`trialConfirmed` 为可选兼容字段，不参与准入 | 房主；仅大厅、结束或暂停时更改；语音只要求播放器准备就绪及有效主持状态，试音可选 |
| `guard`、`seer` | `targetId` | 对应存活角色当前窗口 |
| `wolf_propose` | `targetId` | 活狼当前窗口，个人提议仍可修改 |
| `wolf_confirm` | `consensusId` | 活狼，携带本人私密视图中的最新提议版本 |
| `witch` | `choice` 为 save、poison、pass，及 `targetId` | 合法药剂与自救规则；pass 的目标必须为 null |
| `hunter` | `targetId` | 已公告且本次合法待反应猎人，公开播报完成后开放；不能射击本人 |
| `day_draft` | `targetId` | 白天房主，null 表示明确无人出局 |
| `day_confirm`、`day_publish` | `draftId` | 房主，来自最新房主草案视图；发布须已确认 |
| `pause`、`resume`、`abort`、`restart` | 无 | 原房主；恢复要求主持可用，重开要求本局已结束 |

客户端不能调用核心的 `deal`、`open_window`、`close_window`、`finish_role` 或 `publish_dawn` 原始命令。公开指令统一经过 `cue_ack`，截止时间统一经过协调器检查。

身份查看为只读。新局不再保存 `roleAcknowledgements`，旧快照中的此字段不参与首夜推进。本人响应保留旧的 `acknowledged` 布尔字段以兼容 `/api/v2` 结构，值只表示角色已经发放，不是玩家查看或点击的记录；当前网页不展示或使用它。旧 `acknowledge` 请求可返回去重回执，但不能公开身份、推进阶段或代替行动确认。

## 去重与冲突

同一身份、房间和请求编号保存内容指纹及回执。相同内容重试返回原回执，内容改变则 `REQUEST_ID_REUSED`。去重事实不会因服务重启丢失。加入也绑定大厅编号，新局不能消费旧加入请求。

每次写入先读取最新状态，按规则产生新快照，再比较内部存储版本写入；冲突最多重新读取并校验四次，之后返回 `WRITE_CONFLICT`。不能把第一次计算出的旧快照重新覆盖到新状态上。

公开 `revision` 只跟随公开投影变化。私密动作、个人确认、白天草案和心跳不会增加公开版本或公开行动计数；房主没有剩余行动者名单。`windowId` 随公开阶段、暂停、恢复、主持方式或待播公告改变，旧窗口请求被拒绝。狼队与白天草案的版本仅进入对应合法私密响应，暂停恢复不改变已有目标内容。

公开 `narration` 仅含方式、音频版本与待播公告编号及公开事件范围；没有私人知识或行动人数。语音模式保存待播公告，禁止在公告结束前开始夜晚、推进指令、发布下一投票、开枪或重开。文本回退保留未完成公告，必须明确读完再继续。旧快照没有此字段时按文字模式解释，不清空本地旧房间。

播放器只从公共投影生成序列。播完后的请求固定携带序列开始时的局、窗口、公告与请求编号，不能套用后来轮询的窗口。已接受回执后的页面同步必须等旧轮询结束，再发起新的读取，不能复用操作前的旧响应。

语音房间持久保存启用时校验过的音频版本。当前为 `host-zh-v3`；升级后，原语音快照缺少版本或仍绑定旧版时暂停，保留剩余时间、行动、公告和资源；当前版本播放器重新准备后可恢复，无需试音确认。语音心跳必须携带匹配的 `narrationVersion`，新的完成请求缺少或携带旧版本会被拒绝。历史已接受请求仍可返回原去重回执，但不推进当前阶段。文字模式不要求音频心跳版本，可以明确切回文字继续。

## 协调与数据保留

房主每 3 秒上报前台心跳，连续 10 秒没有有效心跳时暂停。`foreground: false` 或 `audioReady: false` 也暂停。新的有效心跳不自动恢复；原房主必须重新同步并发出 `resume`。

文字模式上报 `audioReady: true` 表示文字主持可继续，不宣称已经播放声音。语音模式结合完整资源解码与实际 AudioContext 状态上报，不依赖试听确认；资源失败、中断、后台或刷新时不可继续推进。多标签页通过租约与 BroadcastChannel 选出唯一活跃主持页；原房主的第二标签页不等于主持接管。

截止时间检查由公共同步、动作和心跳请求触发，没有依赖浏览器计时器推进的权威逻辑，也没有后台常驻 tick。守卫30秒、狼人30秒、女巫和预言家10秒。固定窗内提前完成仍等待截止时间；狼人超时未全体确认则自动等待，保留目标与确认并允许存活狼人继续协商，最后一人确认后闭窗。不提供手动狼人暂停命令。其他未完成行动安全暂停，不代选。恢复保留剩余毫秒并增加本角色窗口长度。猎人公开公告完成后才开10秒窗口，超时安全暂停而非代为弃枪。

房间及结束档案默认保留 24 小时。改变实际游戏事实才延长房间期限；档案按该局结束时间保留，后续新局不无限续期旧档案。访问时严格校验到期；云端每五分钟独立清理，并裁剪到期嵌入档案、增加存储CAS版本。不能声称无请求时本地文件已经立即物理删除。

限额每分钟计数并持久化：会话初始化全局 120，建房每会话 5 及全局 30，加入每会话 20 及全局 300，命令每会话 120，房主心跳每会话 40，HTTP 每会话 240。它们是本地首版保护，不替代线上受信任来源地址限制或攻击压力测试。

## 错误处理

| HTTP | 典型错误 | 页面处理 |
| --- | --- | --- |
| 400、413、415 | 输入、配置、请求体或类型不合法 | 修正输入，不盲目重试 |
| 401 | `INVALID_SESSION` | 原会话无法验证，不按昵称接管；不能用新凭据读取旧席位 |
| 403 | `FORBIDDEN`、同源校验失败 | 停止越权路径，不显示秘密详情 |
| 404 | `ROOM_UNAVAILABLE`、未知接口 | 房间失效或路径无效 |
| 409 | `STALE_GAME`、`STALE_WINDOW`、`STALE_CONSENSUS`、`STALE_DRAFT` | 同步当前状态，旧草案不迁移，私密新目标重新确认 |
| 409 | 锁定、资格、阶段、准备和有限重试冲突 | 显示对应当前任务错误；不更改已接受结果 |
| 429 | `RATE_LIMITED` | 按 Retry After 等待，仍保留原请求编号 |
| 500 | `INTERNAL_ERROR` | 结果未知时用原编号重试或同步，不展示数据库异常文本 |

响应不回显请求体、凭据、内部快照或原始异常。正式页面还需完成中文错误映射；不把内部错误码当作最终用户文案。
