# 00 产品愿景

更新：2026-10-06。状态：重构工作草案。

## 产品想法

让一桌朋友都能参与多轮狼人杀，用网页替代人工法官的夜晚主持、秘密操作收集、死亡结算和胜负判断。房主负责组织开局与录入白天结果，但不因此知道其他玩家身份。

产品的价值是减少准备和维护负担，同时保留面对面发言、观察和推理的乐趣。手机是操作工具，不应成为白天讨论的中心。

## 已确定的范围

- 场景是朋友的小范围线下聚会。
- 平台限于网页版，不开发 Android、iOS 原生 App 或 WebView 壳。
- 玩家、房主和公共播报使用同一产品的不同视角。
- 保留狼人、预言家、女巫、守卫、猎人、平民六角色的产品范围。
- 白天以线下讨论和投票为主，系统接收最终结果。
- 旧代码先存档，再从新的产品规格准备下一轮开发。

## 首批用户与验证假设

建议首先服务“至少一位组织者懂基本玩法，但大家都希望参与游戏”的熟人局。先验证一个八人推荐板子，再扩大人数与角色组合。

以下是待验证的产品假设，不是现有成绩：

- 每人使用手机带来的入场成本，小于省掉人工法官带来的收益。
- 公共语音与私密手机操作能保留面杀氛围。
- 组织者只需处理准备、白天录入和少量异常，不会变成设备维护员。
- 一局结束后，玩家愿意用同一房间继续下一局。

## 首版承诺

1. 进房和准备简单，身份与座位对应准确。
2. 公共和私密信息隔离，主持人不拥有全知视角。
3. 规则一致，结果可解释，重要分支不会卡住。
4. 刷新、短时断线或声音中断后可以继续游戏。

## 首版边界

首版需要互联网连接。“线下游戏”不等于“无网游戏”。不承诺锁屏或后台持续主持，不加入远程匹配、排名、账号社交、付费体系、复杂角色扩展和单手机传递模式。

PWA 安装可以后续评估，但扫码或打开链接就应能进入游戏，安装不能成为开局条件。

技术栈、数据库和 API 形状尚未确定。旧仓库采用过的技术不自动成为新产品的约束。
